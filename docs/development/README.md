## 共同完成条件

1. 对应需求和设计范围明确，代码及文档一致；不把工程编码选择重新当作已解决的产品问题。
2. 该单元交付物、失败路径与验收同时满足，Review 问题处理后重查。
3. 现有质量门禁不削弱，测试有实际执行结果和环境；未运行、跳过、失败分别保留。
4. Commit、GitHub ref、精确提交 CI、发布和用户安装分别记录。旧证据只证明旧代码，文档调整另做链接/内容检查。
5. 本机权限、凭据、未验证范围与风险明确。现有 moderate 开发依赖告警见[质量指南](../guide/quality.md)，不能称零漏洞。
