# 08 浏览器 SDK 与 MCP 执行

## 目标与边界

实现 D-15 / D-16 已确认的浏览器 SDK 与 MCP 执行接口：与 Codex `26.1103.32239` 相同的浏览器控制能力由 Avru 自己实现；反爬上报不实现；登录与认证协助按 Avru 的来。

技术真源见[浏览器 SDK 设计](../../design/browser-sdk.md)与[MCP 设计](../../design/mcp.md)。本阶段接入真实网页、daemon、QuickJS 与已批准的只读授权切片；不把设计存在当作实现完成。

交付 daemon 的执行进程接线、SDK 能力面、6 个 MCP 工具、确认策略与调用链日志；Windows/macOS 真实子进程与真实浏览器 CI；无需用户账户或外部服务（FRPS 部署与真实登录验收另行排期）。

## 阶段 M2：只读能力

| 项目 | 内容 |
| --- | --- |
| 目标 | AI 能看清浏览器和页面，但还不能改任何东西 |
| 交付物 | 浏览器与标签页发现、显式认领（含标题+URL 快照防 id 复用）；页面结构快照（文本、可操作元素及其引用，含 iframe 说明）；截图（视口/区域，JPEG）；console 日志读取；JS 对话框读取；会话命名（任务开始时命名，扩展侧建标签组并设标题，见 browser-sdk.md“AI 控制可视化”一节） |
| 验收 | 以“在购物网站搜索耳机”为例，AI 能列出标签页、认领目标、读出搜索框与搜索按钮的引用；导航后旧引用明确失效；截图可在回复中查看 |
| 依赖 | M1；元素引用格式与截断规则在 M0 定好 |

## 阶段 M3：写操作

| 项目 | 内容 |
| --- | --- |
| 目标 | 在只读能力的基础上开放受控的写操作，全程先观察再操作再验证 |
| 交付物 | 点击、填入、按键、滚动（元素引用与坐标两种）；页面导航（打开网址、返回、刷新，含协议与受限页面边界）；等待（元素、导航、状态变化、超时与取消）；操作后重新观察验证；虚拟鼠标（每次鼠标动作先动虚拟鼠标再发真实操作）、标签页前台切换（followSessionTab，操作前把被操作标签页切到前台）与 favicon 角标（active / 任务结束两态），见 browser-sdk.md“AI 控制可视化”一节 |
| 验收 | 搜索耳机全流程跑通：填入、点击搜索、等待结果、再读结果；失败步骤能定位到具体哪一步，不从头盲目重跑；重复提交有防护（结果未知时先查页面，不自动重放） |
| 依赖 | M2；确认策略的“操作时确认”分级在 M0 定好 |
