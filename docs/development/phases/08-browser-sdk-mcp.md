# 08 浏览器 SDK 与 MCP 执行

**最新产品合同（D-17，2026-11-08）：** 本阶段执行全自动 AI 浏览器控制；可访问同一设备现在及后续连接的所有可控标签页，所有 CDP 命令/事件通过 SDK 暴露，无命令白名单、单 origin 限制、强制人工认领或操作时确认。仅保留一次性客户端/设备身份连接保护、内部并发锁、失败状态及脱敏审计。此条优先于本阶段的历史草案；技术实现/验收与产品决定分别记录。

## 目标与边界

实现 D-15 / D-16 / D-17 已确认的浏览器 SDK 与 MCP 执行：以 Codex 26.1103.32239 的 22 接口/148 成员为能力对照，由 Avru 原生实现；AI 全自动控制全部已连接可控标签页，不做逐操作授权或人工确认；反爬上报不实现。

技术真源见[浏览器 SDK 设计](../../design/browser-sdk.md)、[MCP 设计](../../design/mcp.md)与 D-17。阶段接入真实网页、daemon、QuickJS 与首次已认证的 MCP 客户端；不把设计存在当作实现完成。

交付 daemon 执行进程接线、全量 CDP 直通与 SDK 高级封装、6 个 MCP 工具、自动执行隔离和调用链审计；Windows/macOS 真实子进程与真实浏览器 CI；不把 FRPS 部署或 npm 发布算作本轮已完成。

### M1 任务拆解（T0–T10，2026-11-08 定稿）

- T0 验收脚本更新为 D-17：浏览器发现后直接执行，无须用户或 AI 先调用认领工具；高级 SDK 和 CDP 均以真实目标调用为验收口径。
- T1 Runner 生产协议：信封 `{v:1,type,taskId,seq}` + `run_task` / `cancel_task` / `ping` / `bridge_call` / `task_result` / `pong` / `bridge_result`（`packages/runner/src/protocol.ts`、`supervisor.ts`、`worker.ts`、`worker.mjs`）。
- T2 超时/取消按生产 timeoutMs（默认 60 秒/上限 300 秒）。
- T3 SDK 空壳：QuickJS 内注入 `browser` 全局，桥接方法名点分路径，非法入参报 `INVALID_ARGUMENT` 不发往扩展。
- T4 Daemon 执行管理器：ExecutionManager、注册表、串行队列 8/1、状态机、终态释放认领（`apps/daemon/src` 新建 `executions.ts`；`package.json` 加 `@avru/runner` 依赖）。
- T6 标签页内部互斥：保留可选的 browser_claim_tab 兼容入口，但 run_script 自动获取目标执行锁；对同一标签页并发冲突返回 TAB_ALREADY_CLAIMED，终态释放。
- T5 桥接检查：任务活跃、客户端/设备连接可信、目标与代次有效、参数正确、并发互斥；不做敏感业务动作审批、确认挂起或 CDP 命令白名单。
- T7 MCP 6 工具接入：迁移到官方 TS SDK（B3，已决定）；`browser_run_script` 提交后立即返回 `{executionId, state, submittedAt}`；`browser_sdk_docs` 用静态最小主题表（B7）；旧名 `browsers_list` 直接改名不留别名（B4，已决定）；新工具统一 `browser_` 前缀。
- T8 Daemon↔extension 动作通道：action / action_result / chunk 分片；扩展需要实现 tabs.list、真实页面读取和无命令白名单的 CDP 调用；新增分片与错误态单测。
- T9 执行日志骨架：步骤记录 + CallTraces 工具白名单扩展到 6 个新工具；独立 SQLite 日志库是 M4，不在 M1 做。
- T10 端到端验收与门禁：真实 Chrome E2E + 任务隔离/超时/取消；门禁只用包级命令（M1 期间不跑全仓库 `pnpm check`，`apps/web` 另有任务在改）。

### M1 实施决定（2026-11-08，M1 内定）

- B2（06 状态核对）：06 文档“浏览器插件和连接流程待重新设计”指的是配对表单 UX 与产品简化（已连接时仍显示完整旧人工配对表单），不是 WS v1 消息合同；v1 合同（pair/pairing/paired/authenticate/ready/tabs/ping/pong/error）已实现并在真实 Chrome 157 / Edge 157 上验收通过，保持稳定。T8 在现有合同上追加 `action` / `action_result` / `chunk` 三种新消息，不改已有消息。
- B5（generation 语义）：daemon 侧为每个 browserId 维护数字代次计数器，每次新连接递增；`run_task` 的 target.generation 与认领记录用该计数器（与 browser-connection.md“连接代次”一致），不直接用 connectionId 充当代次。
- B6（Runner IPC 形态）：按设计改造为 NDJSON 私有管道 + 生产信封（`{v:1,type,taskId,seq}` + 7 种生产消息）；基础的 fork IPC `{run,reply,call,done}` 形态不保留（设计已冻结）；`ping` / `pong` 保活补齐。
- B7（`browser_sdk_docs` 文档源）：静态最小主题表（随 SDK 空壳先给最小主题集，M2/M3 再补）；不从 browser-sdk.md 构建时抽取。
- B8（状态上报值）：M1 验收通过后 `/health` 的 `browserControl` 翻为 `true`；`/api/status` 的 `mcp` 加新值 `browserControl`（与正在改管理页的 web 工作协调文案）。
- `requestUserTakeover` 挂起语义（M1 定义，方法本身随 M3 落地）：调用后任务挂起，执行计时暂停（挂起时长不计入 timeoutMs）；用户完成接管或放弃后，执行以 cancelled 终态（原因 `USER_TAKEOVER`），认领释放。M1 空壳不提供该方法。
- OAuth 的 browser:read / browser:control 目前仅用于首次客户端身份与会话能力标识，不是逐次业务操作批准；已认证客户端无逐操作弹窗。
