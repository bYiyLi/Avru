# 本地管理 Web

本文件拥有人的管理交互，不拥有 daemon 的授权决定。R-15 的职责保留；用户最新纠正按 R-18 收敛为当前浏览器单页，不采用此前多页/跨浏览器管理原型。

## 当前浏览器的单页流程

用户在目标浏览器打开管理页面，只展示这个浏览器的初始化与总览：

1. 当前打开的浏览器未安装 Avru 扩展：进入该浏览器的插件安装流程。
2. 当前打开的浏览器已安装 Avru 扩展：显示总览。

不增加此前原型的多页导航或跨浏览器管理页面。此界面范围不改变底层多个扩展共用一个 daemon，也不改变 AI 发现全部已连接目标的 R-03/R-04；人的初始化页面与 AI 的目标发现是不同使用路径。

“已安装”不能仅由另一个浏览器已经连接推断。如何确认当前浏览器/配置、扩展检测尚未返回时如何呈现、已安装但未配对/离线时的总览行为，需要在这一单页设计下细化；本次不擅自给出探测协议或把安装等同于连接就绪。

## 与当前实现的区别

仓库现有页面是本机配对批准/拒绝、连接配置与普通标签、撤销操作的初版。最新单页流程尚未实现，不能将旧实现或原型当作它的验收证据。认证、管理路由和敏感数据边界见[本机连接合同](browser-connection.md)，本文件不复制 API 定义。

旧视觉原型只保留为被纠正的评审材料，其完整概览、远程连接、活动、设置与多页引导不构成已批准的产品要求。

## 责任与安全边界

CLI 安装后打开本机 Web，扩展安装仍由用户在浏览器要求的流程中确认，不能静默安装。Web 由 daemon 同源托管；页面打开或扩展安装成功不自动批准 MCP OAuth。管理页的敏感入口不能暴露到隧道。

程序安装、daemon 运行、扩展安装、配对连接与远程可用是不同状态。浏览器打开失败而服务健康时 CLI 提供本机私密管理链接，不可公开分享。重启后需重新获取会话能力，关闭页面不停止 daemon。
