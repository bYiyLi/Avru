# 本地管理 Web

本文件拥有人的管理交互；daemon 仍拥有授权决定。当前合同依据 R-18～R-21 和 S-17～S-20，替代 S-16 的旧单页范围。视觉参考为私有 `avru-console-preview` 原型，不把原型模拟数据当作实际运行结果。
2026-11-08 修订：引入手动主题/语言切换、第四页日志页、待办派生区、前端自查诊断与状态驱动安装清单，替代此前“三页、主题语言自动、不提供切换”的条文；旧条文不再有效。设计选型不等于已实现，未实施、未验收前不称已交付。

## 四页与职责

1. **欢迎**：纯落地页。普通入口显示欢迎页，点击“进入 Avru”直接进入管理页面，不根据浏览器或插件状态选择路径。插件工具栏入口显式使用 `#overview`，直接进入管理页面。欢迎页可展示一行式只读状态条（daemon 可达性、已连接浏览器数、扩展版本一致性）；未取得数据时显示“未知”，不据缺失推断未安装或未连接。状态条只读，不改变“点击进入管理页”行为，不自动跳转。
2. **管理页面**：展示服务实际报告的浏览器连接、运行状态和调用记录。用户主动选择“安装扩展”后进入手册；不展示配对请求或批准按钮。停用浏览器连接通过浏览器禁用或移除插件完成。“接下来要做的事”（见下节）和“一键诊断”（见下节）原样放在总览底部，不设独立的“维护诊断”导航或页面；保留指向日志页的入口。
3. **插件安装手册**：状态驱动清单，同时列出 Chrome、Edge 的内部管理地址及手动加载步骤，不读取 UA、不探测插件、不自动打开浏览器。默认目录说明同时列出 dev/prod；取得实际目录时只补充该路径，不据缺失状态推断未安装或要求重装。每一步的状态只能是“已准备 / 已连接 / 未知”，绝不能由缺失数据推断“未安装”。“当前浏览器”取自已连接浏览器的 `metadata.browserName`，未连接时显示未知，不用 UA 嗅探。内部管理地址只提供一键复制按钮，不提供一键打开——浏览器禁止网页打开 `chrome://extensions`，做不出来，不假称可以打开。
4. **日志页**：调用记录的独立完整视图，承载筛选、搜索、导出与复制摘要，以及可展开链路详情（见“本机调用记录合同·独立日志页”）。分页只用 React state，不进 URL hash。

主题默认跟随系统（`prefers-color-scheme`），Header 提供手动亮/暗切换按钮；手动选择写入 localStorage 持久化并覆盖系统跟随。实现以根元素 `[data-theme]` 覆盖 CSS 变量，不新增主题依赖。
语言默认浏览器首选语言（以 `zh` 开头为中文，其余英文），Header 提供手动中/英文切换；手动选择写入 localStorage 持久化。自研 typed catalog：`en.ts` 定义键集，`zh.ts` 必须满足完整键集合；切换不引入远程翻译请求或动态下载。页面 `lang`、文档标题、可访问名称跟随当前选定语言。系统浏览器语言是 Web 可访问的信号，不假称可以读取宿主 OS 的独立语言设置。窄屏保留信息与操作可达性，不把横向溢出当响应式布局。

## 国际化资源与错误边界

Web 的 `src/locales/en.ts` 和 `zh.ts` 是文案唯一来源，组件通过稳定语义键读取，不以中文原文作键，不在调用点同时写两种语言。英文目录定义类型安全键与插值参数，中文必须满足完整键集合；资源一致性测试检查空文案和插值名称。扩展维护独立本地资源，不从 Web 应用跨层导入，不增加远程翻译请求。

当前只有中文、英文与简单命名插值，采用小型类型化资源适配器和平台 `Intl`，不引入未使用的 ICU/动态下载依赖；语言切换为本次新增的已用功能（见“四页与职责”），仍不另引成熟 i18n 库。未来增加复杂语法、多个地区或翻译平台时重新评估成熟库；不能把继续扩展自制模板语法作为默认选择。数字/复数使用 `Intl.NumberFormat`/`PluralRules`，链路日期以选定语言格式显示但固定 UTC，`time.dateTime` 保留 ISO 机器值。用户配置名、工具/事件代码、ID、URL、版本及页面标题是原始业务数据，不翻译。

控制器只暴露稳定错误代码（会话过期、请求失败、连接重试），由 UI 资源映射；不把中文文案当判断条件，不渲染底层异常/响应文本。扩展连接状态同样使用代码及独立配对码字段；翻译不能改变批准/拒绝/撤销权限。插值由 React 文本节点或扩展 `textContent` 渲染，不拼 HTML。页面 `lang`、文档标题、可访问名称也跟随当前选定语言。

扩展 manifest 使用浏览器原生 `_locales`（默认英文，中文 locale 提供对应条目）本地化静态名称/描述；dev/prod 的身份 key 和名称区分保持不变。浏览器管理列表的语言由浏览器原生 locale 规则决定，扩展交互页面仍按本合同的首选语言映射。OAuth 同意页保持扩展独立确认，不因本次资源重构引入 Web 授权入口。

## 真实状态与版本

- 页面打开、会话授权、daemon 连接、扩展安装、扩展连接和 MCP 可用性分别表达。请求失败清除旧在线数据显示，不保留绿色假在线。
- 版本信息来自已认证扩展连接的元数据，不能从管理页面的 UA 填充其他浏览器。User-Agent 降精度时标明来源限制；未上报和离线均显示未知。
- 插件一致性比较 `extensionVersion` 与 daemon 声明的 `expectedExtensionVersion`；浏览器自身版本不是比较目标。一致只说明版本相同，不证明授权、能力或健康。
- 管理接口与扩展协议由[浏览器连接合同](browser-connection.md)拥有。元数据不增加权限，不改变连接的来源与环境限制。

### 安装扩展三步引导（2026-11-10）

安装扩展是独立于五页管理控制台的本机引导视图：沿用全站主题与中英文资源，呈现独立顶栏、步骤导航、实际操作说明和浏览器扩展管理界面**示意图**。侧栏依次为「打开扩展管理」「准备加载扩展」「加载并检查连接」，点击步骤或前进/后退按钮只切换当前步骤正文，不以同页滚动代替切换。由管理页打开安装指南时默认第一步；指定版本锚点则进入第三步。

引导允许使用者明确切换 Chrome 或 Edge，并复制对应 `chrome://extensions/`、`edge://extensions/` 地址，**不自动打开浏览器内部地址，不依据当前管理页 UA 推断浏览器/扩展状态，也不自动安装扩展**。第二步仅在 daemon 确认本环境扩展目录已准备时展示真实绝对路径，未取得时显示未知及默认目录说明，不能等价为未安装。第三步展示已认证连接汇总中的浏览器与插件版本，离线和无元数据保留未知；示意图完全不表示实际安装、开发者模式或启用状态。扩展加载、重新加载和各浏览器权限确认仍须使用者在浏览器里完成。全部新界面用 typed catalog 提供中文/英文，窄屏变为纵向步骤导航，不造成页面级横向溢出。

### 浏览器资料视图（2026-11-10）

管理页面的「浏览器」侧边导航进入独立资料视图，与总览共用已取得的 `ViewState`，不新增连接接口、不按当前管理浏览器的 UA 推断其他浏览器状态，也不从设计原型复制演示配置。展示已登记数量、在线数量，以及浏览器/配置、在线状态、浏览器版本、插件版本、版本检查和最后响应六列；浏览器资料可展开查看完整配置 ID 与已连接浏览器实际上报的标签页。使用侧边栏前端状态切换，不在 URL hash 添加可分享路由。

只有已连接且有认证元数据的浏览器才展示已报告版本；离线配置的旧元数据与标签页不可当作当前信息。版本一致性仅比较插件版本与 daemon 期望插件版本，任一缺失显示未知，不能宣称兼容性已验收。当前管理 API 没有可信最后响应时间，整列明确显示未知，不推算或造时间。服务请求失败时，数量与清单按未知/不可用呈现，不能继续显示旧在线数据。

「添加浏览器」进入已有手动插件安装指南；本版本无一键创建连接的后端能力，不自动安装扩展、打开浏览器或虚构已连接配置。中英文文案使用现有 typed catalog；深浅主题与窄屏表格滚动沿用管理 Web 规范。

## 接下来要做的事（派生区）

总览底部的“接下来要做的事”派生区：全部输入来自已有 `ViewState`，不新增接口、不新增轮询、不据缺失数据推断。任一输入为未知时，对应条目不出现（不把未知说成待办）；全部无待办时显示明确空状态，不留空白歧义。

触发条件、影响排序与直达目标（第一版规则；触发条件与排序在实施中定，以实施验收为准）：

| #   | 触发条件（以 `ViewState` 为准）                                                 | 直达目标            |
| --- | ------------------------------------------------------------------------------- | ------------------- |
| 1   | 浏览器未连接（无已认证扩展连接）                                                | 插件安装手册页      |
| 2   | 扩展版本不一致（`extensionVersion` ≠ daemon 声明的 `expectedExtensionVersion`） | 安装手册页 / 版本区 |
| 3   | MCP 未启用或不可用                                                              | 连接方式 / MCP 入口 |
| 4   | 远程连接未配置                                                                  | 远程连接配置入口    |

按影响从大到小排序，即上表顺序；同一影响等级保持表内顺序。每条只做一件事：说明问题与直达目标，不在派生区内展开修复流程。

## 一键诊断（前端自查）

总览底部提供一键诊断入口：纯前端自查，复用已有轮询端点加 `GET /health` 逐项重查（daemon 可达、会话/连接状态、扩展连接与版本、MCP 可用性），逐项报告通过 / 失败 / 未知，并指出哪一步断了。不新增 `/api/diagnostics`（延后到第 4 步，见阶段文档）。诊断失败只报告观测到的断点，不据失败推断未安装，不造修复结论；未取得的项显示未知。

## 视觉方向

**全站只有一套视觉基础**：以欢迎页为 Avru 品牌与界面基准。欢迎、插件安装与五个控制台工作页面共用 `style.css` 根级语义变量（背景、文字、品牌蓝色、边框、抬升表面、强调浅底和阴影）；`console-shell.css` 的页面变量只能映射这些语义变量，不得另设一套深浅主题或紫色品牌强调。成功、失败、拒绝与未知等业务语义颜色可独立表达，但不能取代全站品牌色。按钮、字号、字体与圆角遵循同一基础规范，局部组件仅按功能差异布局。

桌面五个工作页面使用固定左侧独立导航、共用顶部栏、右侧单页内容；导航切换页面而非滚动到总览内的锚点。主内容宽度只减一次侧栏宽度，宽屏充分使用剩余空间、窄屏重排内容且不产生页面级横向溢出。

不要浅绿、现代化简约。采用中性灰阶加单一蓝色强调色：

- `--paper` 由 `#f8faf6` 改为 `#f7f8fa`（中性灰白）；
- 删除 `--green #396a54`，不再用绿色作主强调色；
- `--button` 由 `#315c47` 改为 `#2563eb`，与单一蓝色强调色一致（强调色变量名为 `--accent`，值为 `#2563eb`，按钮沿用该值）。
- 亮/暗两套主题均遵循同一方向：中性灰阶底色加同一蓝色强调色；暗色变量值在实施中定。语义色（成功/错误等）如需保留须另行定义，不得复用为品牌主色。

## 铁律（保留）

以下条文在本次修订后继续有效，新增 UI 同样受其约束：

- 不读取 UA、不探测插件、不自动打开浏览器。
- 不据缺失状态推断未安装、未连接或要求重装；未取得的任何状态一律显示“未知”。
- 日志只展示真实 span（request / authorization / dispatch 三类），不造 SDK/执行/扩展步骤，不造假数据，不用示例日志填充产品。
- 每个新增 UI 状态（主题、语言、状态条、待办、诊断、安装清单、日志筛选结果）必须显式保留“未知”态；请求失败清空旧在线数据，不保留绿色假在线。

## 本机访问与自动连接

按 2026-11-08 确认的本机信任方案，管理页面可以直接打开普通本机地址，不要求浏览器持有管理凭据。旧 `#key=` 链接仍兼容并清除 fragment；它不是页面功能的前置条件。启动器确认实例和退出进程的接口继续单独验证实例凭据。来源、Host、dev/prod 隔离和远程 OAuth 保护由[连接合同](browser-connection.md)维护。

插件加载后在后台自动连接对应环境，工具栏图标直接打开本机管理页面。插件不提供安装/配对弹窗，不要求六位码或管理页批准。旧协议仅用于升级期间已连接旧插件的兼容，不作为新用户操作路径。页面不发送扩展探测或一次性票据请求；获取实际服务数据失败时显示暂不可用并清空旧状态。

## 连接方式与链路观测

ChatGPT 通道及 FRPC 是两个连接配置入口；只有真实支持的后端才能保存、测试连接或声称可用。当前未实现时只展示说明和状态，不保存虚假配置、生成假的 MCP URL 或要求用户提交秘密。

最终 MCP 详情要求实际 Trace ID、Request ID、Span/Parent、逐步骤时间/耗时、结果和关联脱敏日志；未知结果不能归为失败，更不能盲重放。没有执行记录源时展示明确空状态，不用示例日志填充产品。严禁日志包含 bearer、配对凭据、cookie、完整参数、私密页面内容及带秘密的 URL。

### 本机调用记录合同

连接配置、自动管理状态及固定连接活动从本机 `/api/connection` 获取，交互和秘密边界归[MCP 合同](mcp.md)与[连接指南](../guide/connection.md)维护。管理页以“远程连接”呈现导入和移除，用户不管理 FRPC 进程；与调用记录一样，失联后清空旧状态。代理注册、公网可达性和真实 ChatGPT 联调分别显示。

本机 `GET /api/calls` 采用本机信任及 Host/Origin 校验，不在远程 MCP 端口开放。每个 daemon 在对应环境根的 `browsers.sqlite` 中最多保留最近开始的 200 条 MCP POST 记录；生产数据根的权限与配对库相同，响应声明 `retention.persistent=true`。测试用内存数据库不持久化，声明 `false`。容量满时按开始顺序淘汰，可能淘汰尚在运行的记录；不承诺完整审计留存。删除配对数据库时记录一并删除，升级保留原数据库。

Trace ID、Request ID 和 Span ID 由 daemon 随机生成，不采纳调用方的 ID 作为日志字段。Request ID 通过 `X-Avru-Request-Id` 返回便于定位。只记录允许列表方法/工具名、固定事件代码、时间、单调时钟耗时、父子关系和结果，不记录 RPC ID、参数、响应、异常文本、URL 或认证头。未知方法统一显示 `other`，未知工具为 null。

当前真实步骤仅为服务端请求、授权检查与 MCP 分派。授权拒绝没有分派 span，JSON-RPC 错误即使 HTTP 200 也归为 rejected；内部异常返回固定错误并记 failed，不输出异常内容。无 ID 通知只记 notification_accepted，工具字段为空，不能把 202 接收通知说成工具执行完成。未完成浏览器动作与运行器链路不生成占位 span。本记录表示服务端处理结果，不保证客户端已收到响应；请求开始先持久化 unknown 根 span，完成每个阶段后更新；进程中断时最后一次写入的记录保留 unknown，不能推断实际副作用或客户端是否收到结果。unknown 耗时不展示为已完成耗时，不自动重放。记录写入失败时不保证可观测性；不记录原始异常。

#### 独立日志页

日志页承载调用记录的完整视图：表格和可展开链路详情，将事件与所属 span 一起查看；提供筛选（按结果 / 工具 / 事件）、搜索（按 Trace ID / Request ID / 工具名）、导出与复制摘要。只渲染真实存在的 3 类 span：request（服务端请求）、authorization（授权检查）、dispatch（MCP 分派）；不造 SDK / 执行 / 扩展步骤占位 span。分页只用 React state，不进 URL hash，不新增可分享/可书签的路由状态。空记录及有限本机留存明确说明。请求失败清空旧记录，不能将旧请求状态当成新的在线证据。
