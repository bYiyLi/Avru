# 本地管理 Web

本文件拥有人的管理交互；daemon 仍拥有授权决定。当前合同依据 R-18～R-21 和 S-17～S-20，替代 S-16 的旧单页范围。视觉参考为私有 `avru-console-preview` 原型，不把原型模拟数据当作实际运行结果。

## 三页与职责

1. **欢迎**：每次进入先显示欢迎页，维持绿色品牌与留白；不在首屏塞管理表格。继续设置后才判断当前浏览器连接。
2. **安装与连接引导**：只针对当前浏览器配置进行本地扩展安装与连接引导。浏览器名称提示可以来自 UA，但不能据此推断是否安装扩展。Chrome/Edge 采用开发者模式与“加载已解压的扩展”；不能静默安装或把普通页面按钮伪装成能直接打开浏览器受限管理页面。复制管理地址、复制真实稳定扩展目录与安装后复查属于目标体验。
3. **系统总览**：展示整个 Avru，含守护进程、已配对/在线浏览器和标签、连接方式及调用观测。当前浏览器仅可作为列表附加标识，不能用它替代全系统状态。使用连续行、表格和分隔线，不采用大型卡片堆叠。

主题通过 `prefers-color-scheme` 跟随系统；语言按浏览器首选语言，以 `zh` 开头使用中文，其余英文，不提供主题或语言切换。系统浏览器语言是 Web 可访问的信号，不假称可以读取宿主 OS 的独立语言设置。窄屏保留信息与操作可达性，不把横向溢出当响应式布局。

## 国际化资源与错误边界

Web 的 `src/locales/en.ts` 和 `zh.ts` 是文案唯一来源，组件通过稳定语义键读取，不以中文原文作键，不在调用点同时写两种语言。英文目录定义类型安全键与插值参数，中文必须满足完整键集合；资源一致性测试检查空文案和插值名称。扩展维护独立本地资源，不从 Web 应用跨层导入，不增加远程翻译请求。

当前只有中文、英文与简单命名插值，采用小型类型化资源适配器和平台 `Intl`，不引入未使用的 ICU/动态下载/语言切换依赖。未来增加复杂语法、多个地区或翻译平台时重新评估成熟库；不能把继续扩展自制模板语法作为默认选择。数字/复数使用 `Intl.NumberFormat`/`PluralRules`，链路日期以选定语言格式显示但固定 UTC，`time.dateTime` 保留 ISO 机器值。用户配置名、工具/事件代码、ID、URL、版本及页面标题是原始业务数据，不翻译。

控制器只暴露稳定错误代码（会话过期、请求失败、连接重试），由 UI 资源映射；不把中文文案当判断条件，不渲染底层异常/响应文本。扩展连接状态同样使用代码及独立配对码字段；翻译不能改变批准/拒绝/撤销权限。插值由 React 文本节点或扩展 `textContent` 渲染，不拼 HTML。页面 `lang`、文档标题、可访问名称也跟随首选语言。

扩展 manifest 使用浏览器原生 `_locales`（默认英文，中文 locale 提供对应条目）本地化静态名称/描述；dev/prod 的身份 key 和名称区分保持不变。浏览器管理列表的语言由浏览器原生 locale 规则决定，扩展交互页面仍按本合同的首选语言映射。OAuth 同意页保持扩展独立确认，不因本次资源重构引入 Web 授权入口。

## 真实状态与版本

- 页面打开、会话授权、daemon 连接、扩展安装、扩展配对和 MCP 可用性分别表达。请求失败清除旧在线数据显示，不保留绿色假在线。
- 版本信息来自已认证扩展连接的元数据，不能从管理页面的 UA 填充其他浏览器。User-Agent 降精度时标明来源限制；未上报和离线均显示未知。
- 插件一致性比较 `extensionVersion` 与 daemon 声明的 `expectedExtensionVersion`；浏览器自身版本不是比较目标。一致只说明版本相同，不证明授权、能力或健康。
- 管理接口与扩展协议由[浏览器连接合同](browser-connection.md)拥有。元数据不增加权限，不改变凭据和配对机制。

## 配对与当前浏览器识别边界

同一标签页重新打开完整私密管理链接时，合法的新 `#key=` capability 触发页面重载，由既有初始化读取并立即移除 fragment；不把旧会话复用为新授权。无关或格式错误的 fragment 不触发重载。

新安装采用已认证管理页与当前浏览器扩展的原 WS 一次性票据握手，详见[连接合同](browser-connection.md)。旧版六位码批准保留为兼容路径；不能因取消手填短码的 UI 目标而让任意扩展 Origin 自动获准。

新 Web 不用另一个浏览器在线来判定当前浏览器已安装；可信当前配置握手未完成前，明确显示无法判断并提供安装、启用、隐私模式排查及“查看系统总览”入口。浏览器/配置自动匹配由精确 sender 与一次性票据完成；只有实际扩展响应可显示版本，只有原连接 ready 后可显示已连接，不能用前端猜测替代。

## 连接方式与链路观测

ChatGPT 通道及 FRPC 是两个连接配置入口；只有真实支持的后端才能保存、测试连接或声称可用。当前未实现时只展示说明和状态，不保存虚假配置、生成假的 MCP URL 或要求用户提交秘密。

最终 MCP 详情要求实际 Trace ID、Request ID、Span/Parent、逐步骤时间/耗时、结果和关联脱敏日志；未知结果不能归为失败，更不能盲重放。没有执行记录源时展示明确空状态，不用示例日志填充产品。严禁日志包含 bearer、配对凭据、cookie、完整参数、私密页面内容及带秘密的 URL。

### 本机调用记录合同

连接配置、自动管理状态及固定连接活动从本机 `/api/connection` 获取，交互和秘密边界归[MCP 合同](mcp.md)与[连接指南](../guide/connection.md)维护。管理页以“远程连接”呈现导入和移除，用户不管理 FRPC 进程；与调用记录一样，失联后清空旧状态。代理注册、公网可达性和真实 ChatGPT 联调分别显示。

本机 `GET /api/calls` 复用管理 capability、Host/Origin 校验，不在远程 MCP 端口开放。每个 daemon 在对应环境根的 `browsers.sqlite` 中最多保留最近开始的 200 条 MCP POST 记录；生产数据根的权限与配对库相同，响应声明 `retention.persistent=true`。测试用内存数据库不持久化，声明 `false`。容量满时按开始顺序淘汰，可能淘汰尚在运行的记录；不承诺完整审计留存。删除配对数据库时记录一并删除，升级保留原数据库。

Trace ID、Request ID 和 Span ID 由 daemon 随机生成，不采纳调用方的 ID 作为日志字段。Request ID 通过 `X-Avru-Request-Id` 返回便于定位。只记录允许列表方法/工具名、固定事件代码、时间、单调时钟耗时、父子关系和结果，不记录 RPC ID、参数、响应、异常文本、URL 或认证头。未知方法统一显示 `other`，未知工具为 null。

当前真实步骤仅为服务端请求、授权检查与 MCP 分派。授权拒绝没有分派 span，JSON-RPC 错误即使 HTTP 200 也归为 rejected；内部异常返回固定错误并记 failed，不输出异常内容。无 ID 通知只记 notification_accepted，工具字段为空，不能把 202 接收通知说成工具执行完成。未完成浏览器动作与运行器链路不生成占位 span。本记录表示服务端处理结果，不保证客户端已收到响应；请求开始先持久化 unknown 根 span，完成每个阶段后更新；进程中断时最后一次写入的记录保留 unknown，不能推断实际副作用或客户端是否收到结果。unknown 耗时不展示为已完成耗时，不自动重放。记录写入失败时不保证可观测性；不记录原始异常。

管理页展示表格和可展开链路详情，将事件与所属 span 一起查看；空记录及有限本机留存明确说明。请求失败清空旧记录，不能将旧请求状态当成新的在线证据。

## 实施与发布边界

实施范围、验收及缺口见[管理界面阶段](../development/phases/03-management-web.md)。本次迁移不宣称已实现受控 SDK、远程 MCP/OAuth、ChatGPT/FRPC、扩展自动安装、当前浏览器可信握手或完整链路采集。开发包是否携带可加载扩展必须以发行清单核验，不能提供不存在的稳定目录。
