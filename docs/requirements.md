# Avru 产品需求

## 1. 目的与范围

Avru 让 AI 通过 MCP 控制用户正在使用的本机浏览器，减少用户在 AI 与浏览器之间手动选择、切换和操作的步骤。使用体验参考 Codex 的浏览器控制，不承诺复刻其内部实现或获得相同的平台权限。

本文面向项目所有者、开发者和验收人员，拥有产品要求及验收口径。技术设计见 [design.md](design.md)，决策与待定项见 [decisions.md](design/decisions.md)。

本版依据 2026-11-07 的项目定义、后续 CLI 职责、受控脚本及 WS + CDP/扩展 API 选型确认对话整理。已确认要求与助手提出但尚未完成确认的功能建议分开记录。当前已实现本机连接与安装生命周期子集；这些不满足下列完整产品验收，具体进度见 [开发计划](development/README.md)。

## 2. 参与者与系统环境

- **电脑使用者**：安装软件、安装扩展，在目标电脑上确认或管理连接。
- **AI 与 MCP 客户端**：例如 ChatGPT，通过 MCP 发现目标、读取页面、请求浏览器操作。
- **浏览器扩展**：连接到本机守护进程，在浏览器允许的范围内执行请求。
- **本机守护进程**：汇总浏览器连接，提供 MCP、授权处理与本地管理 Web，路由请求和结果。
- **CLI**：通过 npx 提供安装、更新、启动及卸载入口；将浏览器与连接配置交给本地管理 Web。
- **公网入口运营者**：负责 HTTPS 与 FRPS 的可用性、安全配置和可能接触的数据；由谁承担仍待决定。
- **网站与网站账号相关方**：浏览器操作可能读取其数据或改变其状态；Avru 的连接授权不替代网站规则或具体业务操作许可。

用户操作的是自己的既有浏览器会话。关闭、未安装扩展或未连接的浏览器，不属于“所有已连接浏览器”。同一电脑的不同操作系统账号如何隔离，仍未定案。

**R-18（欢迎、管理与安装手册）**：先显示欢迎页，由用户进入管理页面；用户需要安装插件时自行打开安装手册，手动选择浏览器并加载插件。引导不预判浏览器或插件安装状态。插件加载后自动连接本机服务，其图标直接打开管理页面；不要求用户配对或核对短码。来源：2026-11-08 本次会话确认的手动安装与本机信任方案，取代 S-17、S-18 中与此冲突的引导选择。验收：覆盖无管理会话、首次加载、重启恢复、多个浏览器配置和 dev/prod 隔离；状态不可用不冒充未安装。实现及本地验证已完成；品牌浏览器和平台验收边界见[安装阶段记录](development/phases/02-installer.md#2026-11-08-手动安装与本机自动连接)。

**R-19（系统外观与语言）**：主题跟随系统亮暗，中文首选语言显示中文，其余英文，不提供手动切换。来源 S-17。验收：系统亮暗与中英文组合及窄屏可读，识别限制明确。

**R-20（全系统与版本）**：总览集中展示 daemon、全部已对接浏览器状态、浏览器版本、插件版本和插件预期版本的一致性。采用紧凑非卡片界面。来源 S-19、S-20。验收：不同浏览器元数据不串用；版本未知/不一致/一致、离线和授权状态独立。

**R-21（真实调用观测）**：MCP 调用详情关联实际链路步骤与脱敏日志，支持故障定位；没有实际后端时明确不可用，不使用模拟日志。来源 S-19、S-20。验收：Trace/Request/Span 对应，步骤耗时、错误和结果未知可区分，不暴露凭据或页面私密信息。完整采集后端未实现，不能以空状态页面作为此项完成。

**R-04 的范围说明**：已确认的是全部已连接浏览器可用、不逐个要求用户选定操作目标。现有授权是否自动覆盖以后新增的浏览器连接，属于授权生命周期问题，见 Q-04；不能借此恢复“每次操作先让用户选浏览器”的交互。

**R-08 的判定说明**：“同机”指确认经目标电脑的受信本机组件完成。公网请求经过隧道、来自相同公网 IP 或携带设备名称，都不能单独证明同机。具体证明机制见技术设计候选及 Q-03。

**R-10 的判定说明**：取消的是用户管理 token 的交互要求。OAuth 和组件之间仍需要系统自动管理的身份凭据，不能解释为公网接口无需认证。

**R-11、R-13、R-14 的状态说明**：命令是已确认的目标接口，本地 bundle 已有安装/修复/卸载测试；尚未发布到 npm，不能据此声称用户可直接从 registry 安装。安装入口依赖用户自备 Node.js/npm；当前 bundle 版本范围见安装设计，正式发行和最终平台矩阵仍待 Q-06。

**R-13 的版本范围**：比较本次运行的安装包与本机版本，不从版本号相同推断文件相同或 registry 已无更新。退出或拒绝更新不修改安装；非交互 `avru --yes` 保留自动安装/修复行为，旧包不自动降级。

**R-15 与 R-04 的关系**：S-17～S-20 将 Web 调整为三页及全系统总览；这不恢复“AI 每次操作前需要用户手动选浏览器或标签页”的要求。

## 4. 已提出、尚未冻结的功能范围

此前方案提出以下基础操作，适合用于后续最小闭环设计，但尚没有逐项确认完整语义、权限或支持矩阵：

- 读取页面结构或文本、截图。
- 点击、输入及标签页操作。
- 通过 MCP 查询连接/控制状态、停止当前控制、撤销授权。R-15 已确认本地 Web 承担运行状态展示，不代表这些 MCP 接口与授权管理动作已经定案。

R-16 已确认受控浏览器 SDK 脚本和 QuickJS 进程选择，不代表任意系统访问或无限制执行。以下具体能力仍未定案：滚动、导航、表单提交、快捷键、跨框架操作、下载、上传、任意页面 JavaScript、持续 JS 会话，以及脚本保存和重复执行。它们不能因“参考某项目”而自动进入首版承诺。

产品默认可见全部已连接标签页，与网站访问权限、隐身窗口权限、敏感操作许可是不同层次。浏览器不允许扩展访问的页面不能绕过；具体授权粒度待 Q-05 决定。

## 5. 约束、依赖与非目标

- 扩展安装需要遵守浏览器支持的安装与用户确认流程；npx 是引导入口，不承诺静默安装。
- 用户自备 Node.js/npm，Avru CLI 不负责安装这两个前置依赖；当前 bundle 支持范围见安装设计，最终发行矩阵仍待定（S-10）。
- npx 入口不等于常驻进程本身。CLI 生命周期职责已确认；现有持久位置、自启动实现、升级恢复与数据清理见安装设计；发行和真实登录验收另行记录。
- 当前“自启动”按用户登录后的桌面会话解释，不承诺无人登录时控制用户浏览器。
- 用户退出、电脑休眠、浏览器关闭、扩展离线或网络中断会影响可用性，恢复语义必须说明。
- FRP 提供连接，不替代 OAuth、本机组件认证或页面操作权限检查。
- 没有批准默认开放调试端口、任意文件系统访问或通用 shell 执行。
- Avru 的连接许可不能自动授权付款、删除数据、发送消息等具体网站操作。
- 当前只确认受控浏览器 SDK 脚本，不包含 Giunto 的通用 SDK 扩展平台，也不自动继承 Kivo 的脚本保存与工作流能力。
- 扩展工程采用 WXT + TypeScript，开发包管理继续使用 pnpm（S-14、D-13）；这是实现约束，不改变用户自备 Node.js/npm 后通过 npx 使用的体验。初始开发版本、目录与骨架构建见 [架构](design/architecture.md)与开发计划；真实控制扩展与跨平台验收仍待 Q-15/Q-10。
- 服务端 HTTP 采用 Fastify，本机 WS 库采用 ws，MCP 使用官方 TypeScript SDK；管理 Web 采用 React + Vite，持久化采用 SQLite 且暂不引入 ORM，测试采用 Vitest + Playwright（S-15、D-14）。这是工程选型约束；初始开发依赖版本已固定；数据迁移、协议接线和完整测试矩阵仍见 [架构](design/architecture.md)、Q-16。
- 上述选型不确定云端租户体系、商业模式或发布许可，也不替代 QuickJS 具体 WASM 包、IPC、同机授权和扩展配对的后续设计。
- 性能、容量、可用性指标与最低操作系统/浏览器版本没有已批准数值；不能填写任意目标并称为承诺。
